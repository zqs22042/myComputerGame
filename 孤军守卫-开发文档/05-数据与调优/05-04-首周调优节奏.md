# 05-04 · 首周调优节奏

> 模块：05 数据与调优 ｜ 索引：[README](../README.md)

| 天数 | 关注重点 | 动作阈值 |
|---|---|---|
| D1 | 单局时长、首次死亡波次 | 中位数存活 <3min → 下调 `hp_step_growth` 5–10%；>8min → 下调 `soft_*_cap` 或 `hp_step_growth`，跑长局复测 |
| D2–D3 | 广告渗透率、复活使用率 | 渗透率 <40% → 检查广告按钮是否显眼或提高奖励 |
| D4–D5 | 升级选择分布 | 某升级项选取率 <5% 或 >40% → 调 `upgrade_*.csv` 的 `effect_value` 或 `cost_gold` |
| D6–D7 | 循环数分布、Boss 循环留存 | 多数玩家撑不过循环 1 Boss → 下调 `hp_step_growth` 或 `boss_wave_step_extra` |

## 调参冻结原则

- 每次只动一张表的一类字段，改完跑 `npm run config` 重新生成 `config.json`。
- 优先动 `endless_config.csv`（`hp_step_growth`、`boss_wave_step_extra`、`soft_*`），其次动 `upgrade_*.csv`（`cost_gold`、`effect_value`），最后动 `monsters.csv`（`hp_base`、`spawn_weight`）。
- `boss_phase_events.csv` 与 `boss_skill_timeline.csv` 非调参期不动，避免时序归因混乱。

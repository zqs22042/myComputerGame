# 05-05 · 本局日志导出规范

> 模块：05 数据与调优 ｜ 索引：[README](../README.md)

## 一、目标

内部试玩时，每个试玩者的每一局都要能一键导出结构化日志，用来回答三件事：这局撑了多久、哪一波压力异常、金币花到哪去了。

## 二、按钮位置与交互

- **位置**：结算页右下角，与“再来一局”并列，图标用 ⤓。
- **文案**：`导出本局日志`。
- **点击行为**：
  - Web / 编辑器预览：生成 JSON Blob，触发浏览器下载 `battle_<timestamp>.json`。
  - 微信小游戏：写临时文件后调 `wx.shareFileMessage` 或复制到剪贴板，MVP 阶段先用 `wx.setClipboardData` 复制 JSON 文本。
- **状态**：导出成功后按钮置灰 2 秒，显示“已导出”。
- **失败降级**：导出失败时在 console 打印完整 JSON，提示“导出失败，已输出到控制台”。

## 三、JSON 结构

```json
{
  "meta": {
    "version": "1.0",
    "exported_at": "2026-11-19T10:30:00+08:00",
    "result": "defeat",
    "survival_time_sec": 312,
    "cycle_index": 2,
    "rng_seed": 12345,
    "client": "cocos-prototype"
  },
  "battle_summary": {
    "kill_count": 286,
    "wave_index": 17,
    "core_hp_left": 0,
    "gold_earned": 1420,
    "gold_spent": 1380,
    "upgrades_picked": ["EQ_ATK", "SK_DMG", "EQ_ASPD", "UL_DMG"],
    "weapons_bought": ["W01", "W03"],
    "refresh_count": {"coin": 2, "ad": 1}
  },
  "waves": [
    {
      "wave_index": 1,
      "cycle_index": 1,
      "hp_percent_start": 1.0,
      "hp_percent_end": 1.0,
      "leak_count": 0,
      "kill_count": 8,
      "gold_earned": 24,
      "duration_sec": 8.4
    }
  ],
  "events": [
    {"t": 0.0, "type": "run_start", "params": {"rng_seed": 12345}},
    {"t": 2.1, "type": "wave_start", "params": {"wave_index": 1, "cycle_index": 1, "hp_percent": 1.0}},
    {"t": 312.0, "type": "run_end", "params": {"survival_time": 312, "cycle_index": 2, "kill_count": 286, "wave_index": 17}}
  ]
}
```

## 四、字段说明

| 字段 | 来源 | 用途 |
|---|---|---|
| `meta.survival_time_sec` | `run_end.survival_time` | 排名与时长分析 |
| `meta.cycle_index` | 击杀 Boss 次数 | 难度曲线 |
| `meta.rng_seed` | `run_start.rng_seed` | 复现本局 |
| `battle_summary.gold_earned` | `kill.gold_drop` 累计（不含初始 50 金币） | 金币收入曲线 |
| `battle_summary.upgrades_picked` | `upgrade_pick` 序列 | 升级分布分析 |
| `battle_summary.weapons_bought` | `weapon_buy` 序列（只记净购买，拆除不计入） | 武器槽偏好与金币出口 |
| `battle_summary.refresh_count` | `upgrade_refresh` 按 `method` 计数 | 免费/金币/广告刷新占比 |
| `waves[].cycle_index` | 波次所属循环 | 跨循环对比 |
| `events[]` | 全量埋点 | 任意维度下钻 |

## 五、与现有埋点的关系

- `events[]` 直接复用 `05-02` 事件，不新增字段；`screen_clear`、`crit_kill` 按 `01-16` 补充。
- `battle_summary` 与 `waves[]` 是从 `events[]` 聚合出的派生数据，导出时实时计算。
- 导出按钮本身打一个 `log_export` 事件，参数 `{ result, duration_sec }`。

## 六、实现建议

- 在 `BattleModel.ts` 里维护 `events: BattleEvent[]` 数组，所有埋点统一走一个 `emit(type, params)` 方法。
- 结算时 `exportLog()` 从 `events` 聚合出 `battle_summary` 与 `waves`，拼成 JSON。
- Web 端用 `URL.createObjectURL(new Blob([json]))` + `<a download>` 触发下载；小游戏端用 `wx.setClipboardData` 兜底。
- 日志文件名带时间戳，便于多人试玩时收集。
